# query-engine — построитель SQL

## MODIFIED Requirements

### Requirement: План соединения датасетов
Если секции нужны несколько датасетов, построитель SHALL составлять план соединения: базовым берётся датасет метрик, остальные подключаются по связям словаря. При отсутствии прямой связи SHALL искаться кратчайший путь через промежуточные датасеты — они добавляются в план как мост, своих колонок в отчёт не давая. Если пути нет, сборка SHALL отклоняться с указанием, между чем именно нужна связь.

Все датасеты плана SHALL лежать в **одной базе** — на одном подключении: запрос уходит одной базе целиком. Секция, собравшая датасеты одного типа СУБД, но из разных баз, SHALL отклоняться с текстом, называющим подключения; проверки одного лишь типа источника SHALL быть недостаточно — она пропускает десять баз одной СУБД как одну.

#### Scenario: Соединение через справочник
- **WHEN** метрики плана и метрики факта связаны каждая со справочником точек, но не друг с другом
- **THEN** справочник добавляется в план как мост, и секция собирается

#### Scenario: Связи нет
- **WHEN** между датасетами секции нет ни одного пути по связям
- **THEN** сборка отклоняется с сообщением, что нужно завести связь в семантическом слое

#### Scenario: Датасеты из разных баз одной СУБД
- **WHEN** секция обращается к двум датасетам PostgreSQL, лежащим на разных подключениях
- **THEN** сборка отклоняется с указанием обоих подключений, а не уходит в базу первого датасета
