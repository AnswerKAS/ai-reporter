# datasets — реестр источников данных

## ADDED Requirements

### Requirement: Строка подключения датасета
Подключение датасета SHALL задаваться **литеральным DSN** — строкой, из которой
видно СУБД, сервер, порт и базу. Форматы-указатели SHALL отклоняться при
заведении и правке датасета (422): ссылка на переменную окружения (`env:VAR`),
ссылка на сервер метаданных (`app:postgres`) и пустая строка для PostgreSQL,
которая раньше означала то же самое. Отказ SHALL объяснять, что нужен DSN, и
приводить пример для этого типа источника.

DSN Oracle SHALL задаваться в URL-форме `oracle://user:password@host:port/service_name`;
имя сервиса SHALL браться из пути, а SID — из параметра `?sid=`. Порт по
умолчанию — 1521. Логин и пароль SHALL раскодироваться из percent-encoding:
пароль с `@` или `/` иначе разберётся не так. Текст, не начинающийся с
`oracle://`, SHALL отклоняться до обращения к драйверу — иначе ошибка драйвера
вынесла бы наружу дескриптор подключения целиком.

Записи, заведённые до этого правила, SHALL продолжать работать: резолвер старых
форматов остаётся ради них, но новых таких записей система SHALL не создавать.

#### Scenario: Ссылка на переменную окружения
- **WHEN** администратор заводит датасет с DSN `env:DATABASE_URL`
- **THEN** API отвечает 422 и объясняет, что нужен DSN, а не ссылка на переменную

#### Scenario: Метабаза как источник
- **WHEN** администратор заводит postgres-датасет с `app:postgres` или с пустым DSN
- **THEN** API отвечает 422: сервер приложения источником отчётов больше не назначается

#### Scenario: DSN Oracle без имени сервиса
- **WHEN** администратор указывает `oracle://user:pass@host:1521` без пути и без `?sid=`
- **THEN** система отвечает ошибкой с примером правильной формы, а к драйверу не обращается

#### Scenario: Датасет, заведённый раньше
- **WHEN** в реестре есть датасет со ссылкой `env:DATABASE_URL`
- **THEN** он продолжает работать: схема вычитывается, отчёты собираются

## MODIFIED Requirements

### Requirement: Права на датасеты
Просмотр списка, схем и превью SHALL быть доступен любому авторизованному пользователю; создание, изменение, удаление, refresh и загрузка CSV — только администратору.

**Заведение датасета** SHALL происходить в админке (`/admin?tab=datasets`), а не на странице датасетов: там задаётся строка подключения к чужой базе, и место такому — рядом с остальным администрированием. Страница `/datasets` SHALL оставаться каталогом — поиск, фильтры, схема, превью, проверка подключения и черновик словаря — и SHALL вести администратора в админку ссылкой, а не собственной формой.

#### Scenario: Пользователь без прав администратора
- **WHEN** обычный пользователь отправляет запрос на создание или удаление датасета
- **THEN** API возвращает 403

#### Scenario: Администратор заводит датасет
- **WHEN** администратор открывает `/datasets` и хочет завести новый источник
- **THEN** он попадает по ссылке в админку, где форма заведения стоит рядом с пользователями, группами и почтой

## REMOVED Requirements

### Requirement: Ссылки на DSN
**Причина:** форматы-указатели (`env:VAR`, `app:postgres`, пустой DSN для
PostgreSQL) больше не принимаются — строка подключения задаётся литеральным
DSN. Требования к форме DSN Oracle и к маскированию контекста ошибки перенесены
в требование «Строка подключения датасета».

**Миграция:** существующие записи не трогаются; резолвер старых форматов
остаётся ради них до перевода датасетов на подключения.
