# Proposal: dataset-admin-create

## Why

Заведение датасета живёт на `/datasets` — странице, которую открывают все
авторизованные пользователи. Форма спрятана под «Добавить датасет» и видна
только администратору, но по смыслу это администрирование: там задаётся
строка подключения к чужой базе. Всё остальное администрирование уже собрано
в одном месте (`/admin` с вкладками), и датасеты — последнее исключение.

Второе: строка подключения сейчас принимает три формата — литеральный DSN,
ссылку `env:VAR` (в переменной лежит DSN целиком) и `app:postgres` (метабаза
как источник; пустой DSN для postgres означает то же). Форматы-указатели
себя не оправдали:

- `env:VAR` заводит второй, невидимый в интерфейсе слой конфигурации: чтобы
  понять, куда смотрит датасет, надо идти на сервер и читать `.env`;
- `app:postgres` делает метабазу приложения источником отчётов — соседство,
  из-за которого тяжёлый отчёт бьёт по той же базе, где лежат сессии и права;
- проверка «а DSN ли той СУБД лежит в переменной» существует только потому,
  что значение неизвестно до момента подключения.

Строка подключения задаётся одна и явно — DSN.

## What Changes

- **Заведение датасета переезжает в админку**: `/admin?tab=datasets`, панель
  рядом с пользователями, группами, доступами и почтой. На `/datasets`
  остаётся каталог: поиск, фильтры, схема, превью, проверка подключения,
  черновик словаря — и ссылка «Завести датасет» для администратора.
- **Форматы `env:VAR` и `app:postgres` при заведении и правке датасета
  отклоняются** (422) с объяснением; пустой DSN для postgres перестаёт
  означать «сервер приложения» и тоже отклоняется. В форме остаются только
  примеры настоящих DSN.
- **Уже заведённые датасеты продолжают работать**: резолвер этих форматов
  остаётся ради существующих записей (включая дефолтные датасеты витрины со
  ссылкой `env:DATABASE_URL`) и уйдёт вместе с переводом датасетов на
  подключения (изменение `dataset-connections`).

## Capabilities

### New Capabilities

- (нет — расширяются существующие)

### Modified Capabilities

- `datasets` — строка подключения только литеральным DSN; заведение датасета
  в админке (specs/datasets/spec.md)
- `access-control` — вкладка «Датасеты» в админке
  (specs/access-control/spec.md)

## Impact

- Бэкенд: `api/datasets.py` (`_validate_dsn` отклоняет форматы-указатели и
  пустой DSN), `datasets/registry.py` (комментарий: резолвер форматов остаётся
  только ради старых записей).
- Фронт: `components/admin/DatasetsPanel.tsx` (переехавшая форма),
  `pages/AdminPage.tsx` (вкладка и счётчик), `pages/DatasetsPage.tsx` (форма
  уходит, появляется ссылка в админку).
- Тесты: `tests/test_api_datasets.py` — заведение с `env:VAR`, `app:postgres` и
  пустым DSN отклоняется.
- Данные не мигрируют: существующие записи не трогаются.
