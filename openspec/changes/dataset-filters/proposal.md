# Proposal: dataset-filters

## Why

Страница `/datasets` — плитка карточек одним списком, без единого способа её
сузить. Пока датасетов пять, это не мешает; на трёх десятках (а именно столько
их становится, когда к ClickHouse добавляются витрины PostgreSQL, выгрузки
Oracle и загруженные CSV) найти нужный можно только глазами, прокруткой.

Чаще всего сузить надо именно по источнику: «покажи всё, что лежит в PostgreSQL
и в CSV» — потому что при переезде базы, разборе прав или чистке выгрузок
человек работает не с датасетом, а с источником целиком. Одним селектом это не
решается: источников надо выбирать несколько сразу.

Второй вопрос к списку — «что сломано»: статус подключения на карточке есть, но
собрать все карточки со статусом `error` в одном месте нечем, хотя чинят их
пачкой.

## What Changes

- **Фильтр по источникам с множественным выбором** на `/datasets`: ClickHouse,
  PostgreSQL, Oracle, CSV — нажатые складываются по «или», ни одного нажатого
  значит «все». Рядом с каждым — число датасетов, которое даст нажатие.
- **Фильтр по статусу подключения** (`ok` | `new` | `error`) тем же способом:
  сломанные источники собираются в один экран.
- **Поиск** по названию, slug'у, описанию, имени таблицы и **именам полей** —
  «где у нас колонка `revenue`» отвечается без открытия карточек.
- **Выбранные фильтры живут в адресе** (`/datasets?source=postgres,csv&status=error`):
  ссылку на «всё сломанное в Oracle» можно передать коллеге, а возврат «назад»
  не сбрасывает разбор. Строка поиска остаётся черновиком экрана и в адрес не
  идёт — она меняется на каждый символ.
- Над плиткой — счётчик «показано N из M», сброс фильтров и пустое состояние с
  тем же сбросом: список, который схлопнулся в ноль, должен объяснять почему.
- Открытая карточка датасета, выпавшая из фильтра, **закрывается**: панель
  подробностей под плиткой, которой нет в самой плитке, читается как ошибка.
- Новый примитив `Chips` (`components/ui/`) — группа фильтров с множественным
  выбором и счётчиками, рядом с односоставным `Segmented`.

## Capabilities

### New Capabilities

- (нет — расширяются существующие)

### Modified Capabilities

- `datasets` — поиск и фильтры на странице датасетов (specs/datasets/spec.md)
- `web-ui` — примитив `Chips` среди общих (specs/web-ui/spec.md)

## Impact

- Бэкенд не трогается: список датасетов уже приезжает целиком одним `GET
  /api/datasets`, фильтрация — на клиенте. Отдавать фильтр на сервер незачем,
  пока речь о десятках записей, а не о тысячах.
- Код фронта: `components/ui/Chips.tsx` (+ экспорт в `ui/index.ts`),
  `pages/DatasetsPage.tsx` (полоса фильтров, отбор, адрес).
- Права не двигаются: фильтр сужает то, что API и так отдал вызывающему.
