# Proposal: account-tabs

## Why

Кабинет (`/account`) — две панели в ряд: список назначенных отчётов ссылками и
форма смены пароля. Отчётов у сотрудника бывает три десятка, и список без поиска
и порядка бесполезен: нужный отчёт быстрее найти в дереве слева.

Хуже с рассылками. Рассылку заводят на странице отчёта, и увидеть её можно только
там же: чтобы вспомнить, что и кому уходит по утрам, надо обойти все свои отчёты и
открыть в каждом окно рассылки. Свода нет ни на одном экране, хотя запись рассылки
знает своего автора — свод собирается одним запросом.

Админка этот же перекос уже прошла: четыре блока простынёй превратились во вкладки
с адресом (`/admin?tab=access`). Кабинет остался единственной страницей со стопкой
разнородных панелей.

## What Changes

- Кабинет — **вкладки в адресе**: `/account?tab=reports` (по умолчанию),
  `?tab=schedules`, `?tab=security`. Переключатель тот же, что в админке.
- **«Мои отчёты»**: поиск по названию, описанию и slug'у, сортировка (по обновлению,
  по названию), статус сборки, число настроенных рассылок на отчёте, действия
  строкой — открыть, править в конструкторе (по правам), настроить рассылку.
- **Новая вкладка «Мои рассылки»**: все рассылки, заведённые пользователем, в одном
  списке — отчёт, расписание словами, получатели, срок ближайшей отправки, итог
  последней. Оттуда же: включить/выключить, отправить сейчас, **изменить**
  (расписание, формат, получатели, отправитель), удалить и завести новую на любой
  доступный отчёт. Администратор может переключиться на все рассылки системы.
- **Новый метод API `GET /api/schedules`** — свод рассылок: свои (`scope=mine`,
  по умолчанию) либо все (`scope=all`, только админ), с названием отчёта и автором.
  Отдаются только рассылки на отчёты, доступные вызывающему.
- **Правка рассылки в интерфейсе**: `PATCH` расписания существовал, но менять
  рассылку было нечем — окно на странице отчёта умеет только создать и удалить.
- Общая форма рассылки (`components/schedules/`) — одна на окно отчёта и на кабинет;
  `Segmented` и каркас блока (`AdminSection`/`AdminRow` → `Panel`/`PanelRow`)
  переезжают из `components/admin/` в `components/ui/`: их теперь делят две страницы.

## Capabilities

### New Capabilities

- (нет — расширяются существующие)

### Modified Capabilities

- `access-control` — кабинет вкладками: отчёты с поиском, рассылки, безопасность
  (specs/access-control/spec.md)
- `mail-delivery` — свод рассылок пользователя `GET /api/schedules` и правка рассылки
  из кабинета (specs/mail-delivery/spec.md)
- `web-ui` — примитивы `Segmented` и `Panel`/`PanelRow` как общие
  (specs/web-ui/spec.md)

## Impact

- БД: миграции не нужны — запись рассылки уже хранит `author_id` и `report_slug`.
- Код бэкенда: `api/mail.py` (+`GET /api/schedules`), `mail/registry.py`
  (`list_schedules` по автору), `tests/test_routes.py` (опись метода),
  `tests/test_api_mail.py` (тесты свода).
- Код фронта: `pages/AccountPage.tsx` разбирается на панели
  `components/account/{ReportsPanel,SchedulesPanel,SecurityPanel}.tsx`;
  `components/schedules/{ScheduleFields,describe}.tsx`; `components/ScheduleDialog.tsx`
  переходит на общую форму; `components/admin/*` — на `Panel`/`PanelRow` из `ui`.
- Права не двигаются: свод фильтруется теми же `accessible_slugs`, менять рассылку
  по-прежнему может автор или администратор.
