## Context

Вопросы по датасету сейчас превращаются в короткий план полей и агрегатов, а чат отчёта получает одно предложение модели. Адаптеры PostgreSQL, ClickHouse и Oracle уже умеют выполнять SQL. Определение отчёта состоит из секций и хранится вместе с отчётом.

## Goals / Non-Goals

**Goals:** один модуль агента для двух чатов; SQL без ограничений на аналитические конструкции; принудительное чтение; проверяемые SQL-блоки отчёта.

**Non-Goals:** кросс-источниковые соединения и SQL-вопросы по CSV; снятие эксплуатационного предела времени и объёма результата.

## Decisions

- Агент находится в `backend/app/agent`. LangGraph ведёт состояние и условные переходы между узлами решения модели, инструмента и проверки ответа. Число шагов ограничено, чтобы не зациклить диалог.
- Датасет доступен в SQL под именем `dataset` через CTE. Модель не получает DSN или скрытый текст запроса-источника.
- Перед исполнением проверяется один оператор SELECT/WITH и запрет пишущих операторов. PostgreSQL переводится в режим чтения с `statement_timeout`, ClickHouse получает `readonly` и предел времени, Oracle использует транзакцию только для чтения. Проверка текста дополняет, а не заменяет права учётной записи источника.
- SQL-блок отчёта хранит логический SQL и slug датасета. Перед предложением агент проверяет и выполняет его. При просмотре отчёта запрос выполняется заново через тот же механизм чтения; результат превращается в существующие table/chart/kpi секции.
- SQL-блок не принимает общие фильтры конструктора автоматически. Если пользователь включил фильтры, секция показывает явное предупреждение.
- Диалоги хранятся в `agent_conversations` и `agent_messages` по владельцу, виду и цели. В потоковом API вопроса синхронный граф работает в отдельном потоке, а ответ отдаётся событиями NDJSON. Финальную формулировку модель передаёт токенами через `ChatOpenAI.stream`.

## Risks / Trade-offs

- [Источник даёт учётной записи права на побочные эффекты через функции SELECT] → использовать только отдельную учётную запись источника с правами чтения; сервер дополнительно включает режим чтения.
- [Сложный запрос перегружает источник] → таймаут и предел переданных строк; аналитическая агрегация выполняется источником до ограничения выдачи.
- [Модель ошибается в SQL или определении] → ошибка инструмента возвращается как наблюдение, предложение проходит серверную проверку.

## Migration Plan

Миграция БД не нужна: новые поля секции опциональны. Старые отчёты выполняются прежним путём. Откат к предыдущей версии не должен использовать отчёты с SQL-блоками.
