## ADDED Requirements

### Requirement: Аналитический SQL в вопросах к датасету
Система SHALL позволять агенту выполнять один произвольный запрос чтения к выбранному датасету, включая выражения, CTE, JOIN и оконные функции. Система MUST отклонять операторы изменения данных и схемы и выполнять запрос с режимом чтения источника.

#### Scenario: Оконная функция
- **WHEN** агент выполняет SELECT с оконной функцией по выбранному датасету
- **THEN** система возвращает фактические строки результата и текст запроса

#### Scenario: Изменение данных
- **WHEN** агент предлагает UPDATE или изменяющую CTE
- **THEN** система не выполняет запрос и возвращает агенту ошибку

### Requirement: Потоковый ответ по датасету
Система SHALL отправлять промежуточные состояния работы агента и текст ответа потоком и сохранять успешный ход диалога.

#### Scenario: Получение ответа
- **WHEN** сотрудник отправляет вопрос
- **THEN** он видит ход выполнения и текст ответа до завершения всего запроса, а после завершения — таблицу и объяснение

## MODIFIED Requirements

### Requirement: Вопросы по данным датасета
Авторизованный пользователь SHALL задавать вопрос по одному датасету и уточнять его следующим вопросом. Агент SHALL получать историю из метабазы, иметь инструменты схемы, примера строк и аналитического SQL. Сервер SHALL выполнять только запросы чтения с эксплуатационными пределами времени и объёма ответа. Ответ SHALL основываться на результате источника и включать ограниченную таблицу данных; логический SQL к датасету SHALL быть доступен сотруднику по нажатию.

Ответ SHALL включать объяснение: источник, расчёт, группировки, фильтры, сортировку и предел выдачи. Число показанных строк SHALL отличаться от общего числа, когда общее число известно. Наличие следующих строк SHALL проверяться одной дополнительной строкой, без второго полного подсчёта. Лимит результата SHALL объясняться как лимит после аналитического расчёта.

#### Scenario: Уточнение вопроса
- **WHEN** пользователь задаёт следующий вопрос после сохранённого ответа
- **THEN** агент получает вопрос, ответ и SQL предыдущего хода из метабазы

#### Scenario: Неизвестное поле
- **WHEN** SQL агента ссылается на несуществующее поле
- **THEN** инструмент возвращает ошибку агенту для исправления запроса

#### Scenario: Агрегат с фильтром
- **WHEN** пользователь спрашивает сумму по полю и фильтру
- **THEN** ответ объясняет операцию и условие по фактическому запросу

#### Scenario: За пределом выдачи есть строки
- **WHEN** результат содержит больше строк, чем лимит ответа
- **THEN** сотрудник видит число показанных строк и признак продолжения без выдуманного общего числа

#### Scenario: CSV с известным итогом
- **WHEN** ответ построен по устаревшему CSV-датасету и показана только часть результата
- **THEN** ответ различает число показанных строк и фактическое число строк результата
