# Design

`agent_conversations` получает `title` и `saved_at`. Сообщения продолжают записываться автоматически. Кнопка «Сохранить чат» ставит название и время сохранения; список показывает только явно сохранённые диалоги. Пустой чат можно сохранить: сервер создаёт строку диалога.

API списка и сохранения проверяет пользователя, вид (`dataset`/`report`) и цель (`workspace`, `new` или slug отчёта). Запрос сохранения с чужим `conversationId` отклоняется. Кнопка «Новый чат» сразу создаёт пустую строку, чтобы перезагрузка не вернула прошлую беседу. История загружается по идентификатору, чтобы выбор не зависел от последнего открытого диалога. Первый вопрос без идентификатора также создаёт новую строку, не продолжая последнюю.

В чате отчёта при открытии сохранённого диалога используется последнее проверенное определение из сохранённого ответа агента. Для созданного отчёта обычное открытие редактора по slug по-прежнему восстанавливает последний диалог. В интерфейсе оба агента используют одинаковое окно списка сохранённых чатов и поле названия.

Клиент запоминает идентификатор выбранного чата для консультанта и каждого сохранённого отчёта. При перезагрузке он загружает этот идентификатор с проверкой владельца; недоступный идентификатор сбрасывается. Для создания нового отчёта сохранённый выбор не применяется: конструктор остаётся пустым.
