# Design

`ask_datasets` хранит SQL-результаты на уровне всего хода, а не отдельной модели. При переходе на запасную модель в её начальный контекст входят последние проверенные результаты по каждому источнику, включая SQL, колонки, до 20 строк и признак обрезания. Поэтому `finish` может принять финальное действие сразу, если SQL уже выполнен для всех прикреплённых датасетов.

После получения результата по каждому датасету агенту разрешены не более двух дополнительных успешных SQL-запросов. Следующий вызов модели явно требует `final`; повторный выбор инструмента завершает попытку и передаёт накопленные результаты запасной модели. Ошибки SQL не считаются успешными результатами, а прежний общий предел шагов сохраняет защиту от бесконечного исправления.

Финальное действие уже содержит `answer`, подтверждённое SQL и проверками подписей колонок/таблиц. Оно отправляется одним `delta` и сохраняется напрямую. Это убирает отдельную переформулировку, которая добавляла сетевую задержку и могла менять смысл ответа.
