# Design

Детализация SQL-карточки использует зарегистрированный `datasetSlug` и существующую пагинацию сырых строк. Она честно помечает, что произвольный SQL и точка графика не ограничивают сырые строки.

Фильтры SQL-карточки накладываются на CTE `dataset` до пользовательского SELECT. Разрезы берутся из общего словаря или полей определения отчёта; значения передаются параметрами адаптера. Фильтры чужого датасета помечаются неприменёнными.

При сохранении нового отчёта сервер проверяет владельца чернового диалога и меняет его цель с `new` на slug созданного отчёта. При открытии отчёта редактор читает историю по slug.

Рабочий чат вопросов хранит одну историю пользователя с целью `workspace`. Каждый ход указывает ровно один прикреплённый через `@` датасет; выбранный источник показывается у реплики и ответа. Старые маршруты чатов отдельного датасета сохраняются для совместимости.
