# Proposal: dataset-sql-source

## Why

Датасет сегодня — указатель на готовый объект источника (`table_name`: таблица,
представление, матвью). Если нужных данных таким объектом нет, администратор обязан
пойти в чужую базу и создать там вьюху: нужны права на запись, и схема источника
замусоривается объектами, которые нужны только отчётности.

Одновременно даже после заведения датасета он не пригоден в конструкторе: метрики и
разрезы заводятся по одному руками в `/model`, и для витрины из пятнадцати колонок это
пятнадцать форм подряд.

## What Changes

- Датасет может читаться **произвольным SELECT'ом** вместо имени таблицы. Текст запроса
  хранится в реестре и подставляется построителем подзапросом `FROM (<sql>) AS t0` —
  в источник ничего не пишется, данные остаются живыми.
- Контракт адаптера: наружу вместо `quoted_table(table)` отдаётся `source_sql(alias)` —
  единственная точка, где решается «таблица или подзапрос».
- Вычитка схемы и превью работают по запросу: PostgreSQL — описание результата
  (`LIMIT 0`, типы через `pg_type`, комментарии через `ftable`/`ftablecol`),
  ClickHouse — `DESCRIBE (<sql>)`.
- Запрос проверяется перед сохранением: один оператор, только `SELECT`/`WITH`,
  без DML/DDL, для ClickHouse — без подстановок `{имя:Тип}`. Колонки результата обязаны
  иметь непустые и неповторяющиеся имена.
- По вычитанной схеме система предлагает **черновик словаря** — разрезы из строковых и
  датных колонок, метрики из числовых. Администратор подтверждает выбранное галочками,
  и датасет сразу пригоден в `/builder`.
- Выражения метрик проверяются пачкой на одном соединении: заведение пятнадцати метрик
  перестаёт стоить пятнадцати подключений.

## Capabilities

### New Capabilities

- (нет — расширяются существующие)

### Modified Capabilities

- `datasets` — источник датасета: таблица **или** SQL-запрос; вычитка схемы подзапроса;
  контракт адаптера (specs/datasets/spec.md)
- `semantic-model` — черновик словаря по датасету и пакетная проверка выражений
  (specs/semantic-model/spec.md)

## Impact

- БД: колонка `datasets.query` (ALTER, обратно совместимо — у существующих записей NULL).
- API: `query` в контрактах датасета (текст отдаётся только администратору),
  `GET /api/datasets/{slug}/suggest`, `POST /api/datasets/{slug}/semantic`.
- Код: `datasets/{base,postgres,clickhouse,registry,sqlsource}.py`, `semantic/{registry,suggest}.py`,
  `query/builder.py`, `reports/drilldown.py`, `api/datasets.py`, `schemas/dataset.py`;
  фронт — `pages/DatasetsPage.tsx`, `components/DatasetSemanticDraft.tsx`, `lib/api.ts`, `types/dataset.ts`.
- Граница доверия не двигается: SQL источника пишет администратор — ровно как он уже пишет
  выражения метрик и имена таблиц. Пользователь SQL по-прежнему не вводит нигде, его значения
  уходят в запрос параметрами.
