# datasets — реестр источников данных

## ADDED Requirements

### Requirement: Разбор превью датасета
Таблица превью SHALL позволять сортировать строки по любой колонке и
фильтровать их по каждой колонке отдельно.

Сортировка SHALL переключаться щелчком по заголовку по кругу: по возрастанию,
по убыванию, без сортировки — последнее возвращает порядок, в котором строки
пришли из источника. Направление SHALL быть видно в заголовке и объявлено
через `aria-sort`. Сравнение SHALL быть числовым для числовых значений
(`10` идёт после `9`) и словарным для текста.

Фильтр колонки SHALL искать подстроку без учёта регистра; фильтры разных
колонок SHALL складываться по «и». Таблица SHALL показывать, сколько строк
осталось из скольких, и SHALL давать сбросить всё одним действием. Если под
фильтры не попала ни одна строка, таблица SHALL сказать это словами, а не
показывать пустоту.

Разбор SHALL выполняться на клиенте, над уже полученными строками превью:
дополнительных обращений к источнику SHALL не возникать — превью остаётся
дешёвым, а источник не получает запрос на каждое нажатие.

#### Scenario: Сортировка по числовой колонке
- **WHEN** пользователь сортирует превью по колонке с числами
- **THEN** строки идут по величине числа, а не по написанию: `9` перед `10`

#### Scenario: Возврат к исходному порядку
- **WHEN** пользователь щёлкает по одному заголовку трижды
- **THEN** сортировка снимается, и строки снова идут в порядке источника

#### Scenario: Фильтры по двум колонкам
- **WHEN** пользователь задаёт фильтр в колонке региона и в колонке даты
- **THEN** остаются строки, подходящие под оба условия сразу, и видно, сколько их из общего числа

#### Scenario: Под фильтры ничего не попало
- **WHEN** сочетание фильтров не оставляет ни одной строки
- **THEN** таблица объясняет это и предлагает сбросить фильтры

#### Scenario: Разбор не трогает источник
- **WHEN** пользователь сортирует и фильтрует превью
- **THEN** новых запросов к источнику не уходит: всё считается над уже полученными пятьюдесятью строками
