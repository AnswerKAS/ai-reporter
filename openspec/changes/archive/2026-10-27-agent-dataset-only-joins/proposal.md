# Proposal: agent-dataset-only-joins

## Why

Агенту нужен SQL JOIN между прикреплёнными датасетами, но нынешний SQL-контур лишь добавляет CTE `dataset`. Он не запрещает чтение остальных таблиц подключения. Прямой SQL по исходным таблицам нарушает границу датасета.

## What Changes

- Разрешить поддерживаемые СУБД виды JOIN виртуальных отношений прикреплённых датасетов на одном подключении.
- Отклонять физические таблицы и табличные функции во всех уровнях SQL, включая CTE и подзапросы.
- Сохранять список дополнительных датасетов SQL-блока отчёта для повторного исполнения.
- Объяснить агентам имена доступных виртуальных отношений и ограничения подключений.

## Capabilities

### Modified Capabilities

- `agent` — доступные источники SQL для обоих агентов.
- `reports` — исполнение SQL-блоков с несколькими датасетами.
- `report-builder` — сохранение зависимостей SQL-блока от датасетов.
