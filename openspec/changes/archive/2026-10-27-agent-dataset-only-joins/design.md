# Design

В SQL основного датасета используется имя `dataset`. Дополнительные датасеты передаются явным упорядоченным списком и доступны как `dataset_2`, `dataset_3` и так далее. Каждый CTE раскрывает только соответствующий зарегистрированный датасет. Дополнительные датасеты должны иметь тот же тип источника и то же разрешённое подключение, что основной; соединения разных серверов внутри одного SQL не допускаются.

Перед добавлением доверенных CTE сервер разбирает SQL агента в AST по диалекту источника и проверяет все физические ссылки на таблицы во всех областях видимости. Разрешены только имена выданных виртуальных отношений; имена этих отношений нельзя переопределять пользовательским CTE. Табличные функции и квалифицированные имена таблиц не допускаются. Защита чтения на уровне подключения и ограничения времени/строк сохраняются.

Для чата вопросов агент получает таблицу соответствия `datasetSlug` → доступные SQL-имена. Для SQL-блока отчёта список дополнительных slug хранится в `joinDatasetSlugs`, потому что блок исполняется повторно без чата. При предпросмотре агент может указать в этом списке только прикреплённые датасеты. Снятие датасета удаляет зависящие от него SQL-блоки.

Финальная потоковая формулировка ответа по данным — отдельный вызов модели после SQL-цикла. На него также распространяется `CHAT_TIMEOUT`, чтобы ожидание потока имело тот же предел, что и решения агента. Это ограничение выявлено при чтении кода; без доступа к удалённому трейсу оно не доказывает причину задержки конкретной сессии.
