## MODIFIED Requirements

### Requirement: Вопросы по данным датасета
Авторизованный пользователь SHALL задавать вопрос по одному датасету и уточнять его следующим вопросом. Модель SHALL возвращать только структурированный план, а SQL SHALL строить сервер из разрешённых полей и операций. Значения фильтров SHALL передаваться параметрами. Ответ SHALL основываться на результате источника и включать ограниченную таблицу данных; SQL SHALL видеть только администратор.

Ответ SHALL включать объяснение из проверенного плана: источник, операции над полями, группировки, фильтры, сортировку и предел выдачи. Объяснение SHALL соответствовать выполненному запросу и быть доступным сотруднику без SQL. Число показанных строк SHALL отличаться от общего числа, когда общее число известно. Для SQL-источника наличие следующих строк SHALL проверяться одной дополнительной строкой, без второго полного подсчёта. Лимит результата SHALL объясняться как лимит после агрегации.

#### Scenario: Уточнение вопроса
- **WHEN** пользователь задаёт следующий вопрос с историей предыдущего плана
- **THEN** модель получает историю, а сервер вновь проверяет и исполняет новый план

#### Scenario: Неизвестное поле
- **WHEN** план модели ссылается на поле вне схемы выбранного датасета
- **THEN** запрос к источнику не выполняется и пользователь получает понятную ошибку

#### Scenario: Агрегат с фильтром
- **WHEN** пользователь спрашивает сумму по полю и фильтру
- **THEN** ответ объясняет операцию и условие теми названиями, которые есть в схеме датасета

#### Scenario: За пределом выдачи есть строки
- **WHEN** результат SQL-запроса содержит больше строк, чем лимит ответа
- **THEN** сотрудник видит число показанных строк и признак продолжения, но не выдуманное общее число

#### Scenario: CSV с известным итогом
- **WHEN** ответ построен по CSV и показана только часть результата
- **THEN** ответ различает число показанных строк и фактическое число строк результата
