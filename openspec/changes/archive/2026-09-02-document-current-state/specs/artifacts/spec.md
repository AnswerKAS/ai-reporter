# artifacts — хранилище артефактов

## Purpose

Возможность описывает хранение сгенерированных артефактов (скрипты отчётов, CSV-датасеты, файлы черновиков скиллов) через единый фасад хранилища с переключаемым режимом.

## ADDED Requirements

### Requirement: Фасад хранилища
Все обращения к артефактам SHALL выполняться через фасад `services/storage.py` (save/load/exists/delete/path/materialize) с выбором реализации по переменной `ARTIFACTS_STORAGE`; реализация `s3` зарезервирована, сейчас доступен `local`.

#### Scenario: Единая точка доступа
- **WHEN** компоненты системы (компилятор, реестр датасетов, черновики) работают с артефактами
- **THEN** они обращаются только к фасаду, а не к файловой системе напрямую

### Requirement: Local-режим
В режиме `local` артефакты SHALL храниться в каталоге из `ARTIFACTS_DIR` (по умолчанию `backend/artifacts`) с текущим лэйаутом: `<report_id>/report.py`, `datasets/<slug>/data.csv`, `skill_drafts/<id>/skill.md`. Переключение каталога не требует миграции данных.

#### Scenario: Кастомный каталог
- **WHEN** бэкенд запущен с `ARTIFACTS_DIR=/var/lib/ai-reporter/artifacts`
- **THEN** скрипты отчётов, CSV-файлы и черновики создаются и читаются из указанного каталога

### Requirement: Скрипт отчёта для выполнения
Компилятор SHALL располагать `report.py` на диске к моменту запуска subprocess (в S3-режиме — материализация во временный каталог через `materialize`), при этом каноничное место хранения определяется режимом хранилища.

#### Scenario: Сборка отчёта в local-режиме
- **WHEN** воркер собирает отчёт
- **THEN** `report.py` и `datasets.json` лежат в каталоге отчёта, спека после валидации удаляется с диска и хранится в БД
