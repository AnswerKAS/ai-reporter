# Design: document-current-state

## Context

Change документирует текущее поведение системы (см. proposal.md — Why). Источники: `AGENTS.md`, код `backend/app/` и `frontend/src/`, проверенные на живом сервере сценарии. Код не меняется.

## Goals / Non-Goals

**Goals:**
- Зафиксировать стартовые спецификации 6 возможностей: reports, datasets, skills, skill-drafts, access-control, artifacts.
- Формат, который проходит `openspec validate --strict` и станет базой дельт будущих изменений.

**Non-Goals:**
- Полный бэкфилл всех подробностей системы (только наблюдаемое поведение ключевых возможностей).
- Изменения кода, API или БД.

## Decisions

- **Документируем 6 доменов, а не весь проект** — возможности, вокруг которых реально идёт работа; остальные документируются дельтами будущих изменений.
- **Тексты на русском, структурные маркеры — по формату OpenSpec** (ADDED/Requirement/Scenario, SHALL/WHEN/THEN): язык команды — русский, парсер требует только маркеры. Зафиксировано в `openspec/config.yaml` (context).
- **Требования на уровне наблюдаемого поведения** (HTTP-коды, статусы, видимые тексты) без имён функций и модулей — чтобы реализация могла меняться без правки спек.

## Risks / Trade-offs

- [Спеки могут разойтись с кодом при рефакторинге] → дельты будущих изменений обновляют спеки; archive мержит их в `openspec/specs/`.
- [Часть поведения не покрыта стартовыми спеками] → это осознанно: покрытие растёт от реальных изменений, а не от бэкфилла.

## Migration Plan

Только добавление файлов `openspec/`; откат — удаление каталога change. После archive спеки попадут в `openspec/specs/`.
