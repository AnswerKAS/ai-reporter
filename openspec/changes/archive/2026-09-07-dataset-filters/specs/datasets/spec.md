# datasets — реестр источников данных

## ADDED Requirements

### Requirement: Отбор датасетов в интерфейсе
Страница датасетов SHALL давать сузить список: поиском по названию, slug'у,
описанию, имени таблицы и **именам полей** и фильтрами по источнику
(`clickhouse` | `postgres` | `oracle` | `csv`) и по статусу подключения
(`ok` | `new` | `error`). Фильтр источника и фильтр статуса SHALL допускать
**несколько выбранных значений сразу**: выбранные складываются по «или», а
пустой набор SHALL означать «все» — фильтр без выбора не сужает список.

У каждого варианта фильтра SHALL показываться число датасетов, которое даст его
выбор с учётом остальных фильтров; вариант, за которым не осталось ни одного
датасета, SHALL быть недоступен для выбора.

Выбранные фильтры SHALL жить в адресе страницы
(`/datasets?source=postgres,csv&status=error`), чтобы ссылку на выборку можно
было передать, а возврат «назад» её не сбрасывал. Строка поиска в адрес
SHALL не попадать.

Список SHALL сообщать, сколько датасетов показано из общего числа, и SHALL
давать сбросить фильтры одним действием — в том числе когда под фильтры не
попал ни один датасет.

Датасет, открытый на подробном просмотре и выпавший из фильтров, SHALL
закрываться: подробности датасета, которого нет в списке, читаются как ошибка.

Отбор SHALL выполняться на клиенте, над списком, который API уже отдал
вызывающему, и SHALL не расширять видимость: датасет, недоступный человеку,
не появляется ни при каком фильтре.

#### Scenario: Несколько источников сразу
- **WHEN** пользователь выбирает в фильтре источников PostgreSQL и CSV
- **THEN** в списке остаются только датасеты этих двух источников, а счётчик показывает, сколько их из общего числа

#### Scenario: Снятый фильтр
- **WHEN** пользователь снимает последний выбранный источник
- **THEN** список снова показывает датасеты всех источников, а не пустоту

#### Scenario: Все сломанные источники
- **WHEN** пользователь выбирает статус «с ошибкой»
- **THEN** в списке остаются датасеты со статусом `error` — их видно вместе, а не по одной карточке

#### Scenario: Ссылка на выборку
- **WHEN** пользователь открывает `/datasets?source=oracle&status=error`
- **THEN** страница сразу показывает сломанные датасеты Oracle с отмеченными фильтрами

#### Scenario: Поиск по имени колонки
- **WHEN** пользователь ищет `revenue`
- **THEN** в списке остаются датасеты, у которых есть поле с таким именем, даже если в названии датасета этого слова нет

#### Scenario: Под фильтры ничего не попало
- **WHEN** сочетание фильтров не даёт ни одного датасета
- **THEN** страница объясняет это и предлагает сбросить фильтры, а не показывает пустую плитку
