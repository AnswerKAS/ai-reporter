## Context

API уже отдаёт каталог страницами и считает фасеты с учётом прав. Левое меню загружает страницы по мере прокрутки, но при 1500 отчётах это создаёт длинную навигацию рядом с основным содержимым. Полная страница использует плитки, в которых на одну строку приходится мало отчётов.

## Decisions

1. Левое меню служит для быстрых переходов. Без запроса оно показывает закреплённые, недавние и переход в каталог; по запросу или фильтру — ограниченную первую страницу и явную ссылку ко всем результатам. Расширенные фильтры в меню остаются для привычного сценария.
2. Полная страница каталога получает плотные строки вместо плиток. Она запрашивает одну страницу по `offset` и `limit`, а кнопки перехода меняют номер страницы. Так в DOM не накапливаются сотни строк.
3. Поиск, фильтры, сортировка и номер страницы страницы каталога живут в URL. Новый запрос сбрасывает страницу на первую; вход из меню переносит строку поиска и выбранные фильтры.
4. Сервер разбивает поисковую строку на слова и требует совпадения каждого в нормализованном `search_text`. Подстроки остаются допустимыми; порядок слов не важен.

## Risks

- Быстрые изменения поиска могут породить ответы не по порядку. Хук страницы отменяет применение устаревшего ответа.
- Отчёт может исчезнуть при удалении на другой вкладке. Каталог перечитывается после локальных правок и показывает актуальное число/страницу.
- Группировка с десятками групп сама способна создать длинное меню, поэтому результаты групп также ограничены предпросмотром с переходом в каталог.
