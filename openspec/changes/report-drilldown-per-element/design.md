# Design

Исполнитель добавляет идентификатор показателя к KPI и серии графика; для таблицы список показателей остаётся в секции. Фронтенд передаёт `metricKey` в `POST /api/reports/{slug}/drilldown`. Для строки таблицы нажатие на числовую ячейку передаёт её показатель, нажатие на разрез оставляет выбор всех источников секции. Для серии графика берётся ключ исходного показателя, который исполнитель сохраняет даже после разворота второго разреза в серии.

Сервер проверяет, что `metricKey` есть в секции, и выбирает держателей её показателя, а для формулы — держателей обоих операндов. Выбор датасета вне этого списка отклоняется. Секции с произвольным SQL сохраняют текущую оговорку: окно показывает исходные строки датасета, а не результат внутренних условий SQL-блока.

Исполнитель помечает SQL-блок как детализацию по датасету. Клиент открывает его с заголовком «Исходные строки датасета», чтобы не обещать построчную расшифровку агрегированной SQL-ячейки.

Общая кнопка «Сырые данные» принимает только датасет, реально упомянутый в отчёте; принадлежность проверяется до чтения строк. Датасеты операндов формул входят в этот список.

Окно детализации хранит номер последнего запроса. Ответ предыдущего запроса не может перезаписать страницы после выбора нового источника или закрытия окна.
