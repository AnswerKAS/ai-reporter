# skills Specification

## Purpose
Возможность описывает скилл-файлы — markdown-инструкции, по которым LLM-агент генерирует скрипты отчётов: доменную структуру каталога, служебные файлы, правила каркаса и перекомпиляцию.

## Requirements

### Requirement: Доменная структура скиллов
Скиллы SHALL храниться в `backend/skills/<домен>/<имя>.md`; имя скилла — `домен/имя` (например `sales/sales`). Файлы и каталоги с префиксом `_` являются служебными и SHALL не появляться в списке скиллов API и не могут быть использованы для создания отчётов.

#### Scenario: Служебный файл скрыт
- **WHEN** клиент запрашивает `GET /api/skills`
- **THEN** ответ не содержит скиллов, у которых любая часть пути начинается с `_`

### Requirement: Каркас скилла
Скилл SHALL следовать каркасу: заголовок, секции «Цель», «Датасеты» (список slug'ов реестра), «Источник данных» (с полями и требованием синтетического fallback), «Что должно быть в отчёте» (исчерпывающий список секций спеки), «Формат вывода», «Параметры». Правила каркаса и проверка данных описаны в opencode-скилле `report-skill`.

#### Scenario: Привязка датасетов к скиллу
- **WHEN** скилл содержит секцию `## Датасеты: sales_orders`
- **THEN** компилятор передаёт в промпт описание полей только этого датасета и записывает `datasets.json` рядом со скриптом отчёта

### Requirement: Компиляция и перекомпиляция по скиллу
При сборке и перекомпиляции отчёта система SHALL передавать агенту актуальный текст скилла; изменение скилла (новый фильтр/секция) требует перекомпиляции отчёта для вступления в силу.

#### Scenario: Изменение скилла без перекомпиляции
- **WHEN** администратор правит текст скилла существующего отчёта
- **THEN** отчёт продолжает собираться по прежнему скрипту до запуска `POST /api/reports/{slug}/recompile`

### Requirement: Демо-режим по домену
Демо-скрипт (fallback) SHALL строить отчёты для известных доменов (`sales`, `managers`, `sales/drilldown`) на живых данных витрины или синтетике, а для остальных скиллов — generic-отчёт по привязанным датасетам (реальные строки CSV/ClickHouse/PostgreSQL или синтетика по вычитанной схеме).

#### Scenario: Generic-отчёт для нового скилла
- **WHEN** отчёт собирается в режиме demo по скиллу неизвестного домена с привязанным датасетом
- **THEN** спека содержит обзор, KPI по выборке и таблицы-превью данных датасета
