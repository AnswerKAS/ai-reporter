# Скилл-файлы отчётов ai-reporter

Ты помогаешь создавать и править скилл-файлы — markdown-инструкции, по которым
LLM-агент (запускаемый компилятором через `opencode run`) генерирует скрипт
`report.py`. Скрипт пишет JSON-спеку ReportSpec, которую рендерит фронтенд.

Все скиллы следуют ЕДИНОМУ шаблону ниже. Компилятор и публикация проверяют
структуру автоматически (`backend/app/services/skill_template.py`) — скилл,
нарушающий шаблон, не компилируется.

## Расположение и именование

- Каталог: `backend/skills/<домен>/<имя>.md` — строчные латинские буквы,
  цифры, `_` и `-`. Имя скилла = `<домен>/<имя>` (например `sales/sales`).
- Домен = группировка в сайдбаре (`sales`, `reports`, `managers`, `support`,
  `finance`).
- Файлы/папки с префиксом `_` служебные: не видны в `/api/skills` и запрещены
  для создания отчётов.

## Обязательный шаблон (порядок секций фиксировать!)

```markdown
# Скилл: <человекочитаемое название>

## Датасеты: <slug1>, <slug2>

## Цель
<1–3 предложения: что за отчёт и для кого>

## Источник данных
Датасет `<slug>` (postgres/ClickHouse/CSV, таблица `<schema.table>`) — доступ
через `DATASET_<SLUG>_DSN` / `DATABASE_URL`. Если DSN недоступен —
синтетические данные с теми же полями.

Поля таблицы:
- `<поле>` (<тип> — описание)

## Что должно быть в отчёте
1. <секция>: <что именно, формат, сортировка, лимиты>.

## Формат вывода
Скрипт `report.py` при запуске с аргументом `--output <путь>` записывает
JSON-спеку отчёта (ReportSpec; схема описана агенту промптом).

## Параметры
- `period` — месяц в формате YYYY-MM (по умолчанию: текущий месяц).
```

## Правила секций

1. **`## Датасеты: <slug>, ...`** — ОБЯЗАТЕЛЬНА и идёт сразу после
   заголовка. Slug'и — только из реестра датасетов (`GET /api/datasets`).
   Компилятор передаёт агенту только эти датасеты; секция отсутствует или
   пуста — скилл не компилируется. Не переименовывай slug'ы («опечатка»
   может быть настоящим slug'ом, например `tast-field-details`).
2. **`## Цель`** — кратко, 1–3 предложения.
3. **`## Источник данных`** — перечисли поля и типы из РЕАЛЬНОЙ схемы
   датасета. Придумывать поля, таблицы и источники запрещено; если данных
   не хватает — не пиши скилл, объясни, чего нет, и предложи, что можно
   построить на имеющихся полях.
4. **`## Что должно быть в отчёте`** — нумерованный список секций спеки
   (markdown/kpi/chart/table) в нужном порядке. Форматы явные: money —
   целые рубли, percent — пункты (2.4 = 2.4%), форматирование — на фронте.
   Сортировки и LIMIT указывай текстом.
5. **`## Формат вывода`** — зафиксируй контракт `--output`.
6. **`## Параметры`** — опциональна; если параметров нет — напиши «нет».
7. **`## Фильтры`** (опционально) — ключ, label, kind (`select`/`number`/
   `text`), источник options. Скрипт получает значения через `FILTER_<KEY>`,
   select проверяется по options, пустая строка = фильтр выключен.
8. **Детализация по клику** (опционально) — chart-секция содержит блок
   `detail {title, columns, rowsBy}`; ключи `rowsBy` — точные значения xKey
   из `data`. Образец — `backend/skills/sales/drilldown.md`.

## Контекст, видимый агенту

Агент видит только текст скилла и промпт (`backend/app/services/prompt.py`):
схему ReportSpec, мета описаний выбранных датасетов и env
`DATASET_<SLUG>_DSN` / `DATABASE_URL` / `FILTER_<KEY>`. Любое требование
(«сортировка по убыванию», «LIMIT 10», fallback при недоступной БД)
записывай в скилле явно. Только stdlib + `clickhouse_connect` + `psycopg`.

## Демо-режим

Fallback без LLM (`backend/app/services/template_report.py`) знает домены
`sales/*`, `managers/manager`, `reports/*` — прочие скиллы собираются
generic-превью датасетов, полная аналитика только через LLM
(`mode: auto|llm`).

## Проверка после создания/правки

Структурная валидация (из каталога `backend/`):

```bash
.venv/bin/python -c "
import sys; sys.path.insert(0, '.')
from app.services.skill_template import validate_skill_template
validate_skill_template(open('skills/<домен>/<имя>.md').read())
print('валидация пройдена')
"
```

Пересборка существующего отчёта по обновлённому скиллу —
`POST /api/reports/{slug}/recompile`.
