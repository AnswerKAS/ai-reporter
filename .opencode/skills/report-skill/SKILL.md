# Скилл-файлы отчётов ai-reporter

Ты помогаешь создавать и править скилл-файлы — markdown-инструкции, по которым
LLM-агент (запускаемый компилятором `backend/app/compiler.py` через
`opencode run`) генерирует скрипт `report.py`. Скрипт на выходе пишет
JSON-спеку ReportSpec, которую рендерит фронтенд.

## Расположение и именование

- Каталог: `backend/skills/<имя>.md` — имя строчными латинскими буквами
  с дефисами (`sales`, `manager`, `drilldown`). Имя файла = ключ скилла
  в `POST /api/reports {"skill": "<имя>"}`.
- Файлы с префиксом `_` служебные: не видны в `/api/skills` и запрещены
  для создания отчётов.

## Контекст, необходимый скиллу (вшивай в текст, агент его видит)

- Схема ReportSpec и витрины ClickHouse (`analytics.sales_orders`,
  `analytics.manager_stats`) агенту отдаёт промпт `backend/app/prompt.py` —
  в скилле их повторять не нужно, но форматы значений держи явными:
  money — целые рубли, percent — пункты (2.4 = 2.4%), форматирование —
  на фронте.
- Агент видит только текст скилла и промпт. Любое требование («сортировка
  по убыванию», «LIMIT 10», «fallback при недоступной БД») должно быть
  записано явно.

## Обязательная структура файла (в этом порядке)

```markdown
# Скилл: <человекочитаемое название>

## Цель
<1–3 предложения: что за отчёт и для кого>

## Источник данных
Витрина `<таблица>` в ClickHouse. Доступ — переменная окружения
`DATABASE_URL` (DSN). Если DSN не задан или подключение недоступно —
использовать синтетические данные с теми же полями.

Поля таблицы:
- `<поле>` (<тип> — описание)

## Что должно быть в отчёте
1. <секция>: <что именно, формат, сортировка, лимиты>.

## Формат вывода
Скрипт `report.py` при запуске с аргументом `--output <путь>` записывает
JSON-спеку отчёта в формате ReportSpec (схема описана агенту отдельно).

## Параметры
- `period` — месяц в формате YYYY-MM (по умолчанию: текущий месяц).
```

Правила:
- Секция «Что должно быть в отчёте» — нумерованный список секций спеки
  (markdown/kpi/chart/table) в нужном порядке. Ровно то, что должно попасть
  в спеку; ничего не подразумевается по умолчанию.
- Если параметров нет — напиши «нет».
- Пиши кратко и императивно; ограничивай объём (LIMIT в таблицах);
  только stdlib + `clickhouse_connect`.

## Фильтры (опционально)

Если отчёту нужны фильтры — добавь секцию `## Фильтры`: ключ, label,
kind (`select`/`number`/`text`), источник options. Скрипт получает значения
через `FILTER_<KEY>`, select проверяется по options (защита от инъекций),
пустая строка = фильтр выключен.

## Детализация по клику (опционально)

Если нужен drilldown — укажи, что chart-секция содержит блок
`detail {title, columns, rowsBy}`:
- `title` — шаблон с плейсхолдером `{point}`;
- `columns` — колонки таблицы детализации;
- `rowsBy` — словарь: ключ — точное значение xKey точки из `data`
  (символ в символ), значение — строки детализации.

Образец целиком — `backend/skills/drilldown.md`.

## Демо-режим (важно)

Fallback-скрипт без LLM (`backend/app/template_report.py`) знает только
скиллы `sales`, `manager`, `drilldown` (выбор по env `SKILL`). Новый скилл
требует либо правки `template_report.py`, либо LLM-сборки
(`mode: "llm"` в `POST /api/reports`). Предупреди пользователя, если
новый скилл не поддержан демо-режимом.

## Проверка

После создания/правки скилла проверь, что он доступен и компилируется
(из каталога `backend/`):

```bash
# скилл виден в API
curl -s http://localhost:8000/api/skills | jq

# компиляция демо по скиллу (только для sales/manager/drilldown)
.venv/bin/python -c "from app import compiler; import asyncio; asyncio.run(compiler.compile_report({'id':'t','slug':'t','title':'t','skill':'<имя>','params':{}}, mode='demo'))"
```

Для LLM-скиллов демо-компиляция не пройдёт — достаточно, что файл
находится и структура соответствует каркасу. Пересборка существующего
отчёта по обновлённому скиллу — `POST /api/reports/{slug}/recompile`.
