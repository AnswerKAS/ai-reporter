# Скилл: Количество уникальных задач

## Датасеты: tast-field-details, pyrus

## Цель
По каждой форме Pyrus определить количество уникальных задач, созданных по форме, и среднее число заполненных полей на одну задачу (сортировка по убыванию среднего), а также вывести блоками по три последние задачи каждой формы (только номера задач). Предусмотрена фильтрация по номеру формы.

## Источник данных
- Датасет: **tast-field-details** — детали по задачам в Pyrus (postgres, таблица `public.pyrus_form_fields`). Источник данных по задачам и полям.
  | Поле | Тип | Описание |
  |---|---|---|
  | form_id | bigint | Идентификатор формы |
  | task_id | bigint | Идентификатор задачи |
  | field_id | bigint | Идентификатор поля |
  | row_id | bigint | Идентификатор строки (для табличных/повторяющихся полей) |
  | field_name | text | Название поля |
  | field_type | text | Тип поля |
  | field_value | text | Значение поля |
- Датасет: **pyrus** — формы (postgres, таблица `public.pyrus_general`). Источник названий форм. Используются поля: `form_id` (bigint), `form_name` (text).
- Примечание: датасета `pyrus_task`, упомянутого в пожелании, в реестре нет; названия форм берутся из датасета `pyrus` (поле `form_name`) по связи `form_id`.
- В датасетах отсутствует временное поле задач, поэтому «последние задачи» определяются по наибольшим номерам `task_id` (номера задач в Pyrus монотонно растут со временем: чем больше `task_id`, тем позже создана задача).

## Что должно быть в отчёте
1. **Таблица «Уникальные задачи по формам»**
   - Группировка по `form_id` (название формы `form_name` добавляется из датасета `pyrus`).
   - Колонки: `form_id` | `form_name` | уникальных задач | среднее заполненных полей.
   - Уникальные задачи: `COUNT(DISTINCT task_id)` из датасета `tast-field-details` по всем записям выборки в разрезе `form_id`.
   - Критерий «заполнено» для записи поля: `field_value IS NOT NULL AND btrim(field_value) <> ''` (NULL, пустая строка и строка из пробелов — не заполнено).
   - Заполнено полей в задаче: `COUNT(DISTINCT field_id)` по записям, удовлетворяющим критерию «заполнено» (несколько `row_id` одного поля учитываются один раз).
   - Среднее заполненных полей на задачу: среднее арифметическое числа заполненных полей по всем задачам формы.
   - Сортировка: по убыванию среднего заполненных полей; тай-брейк — `form_id` по возрастанию.

2. **Блоки «Три последние задачи по формам»**
   - Для каждой формы из выборки отчёта — отдельный блок с тремя последними задачами.
   - Показывать только номера задач (колонка `task_id`).
   - «Последние» — три задачи с наибольшими `task_id` в рамках формы.
   - Сортировка: `task_id` по убыванию. Если у формы меньше трёх задач — показать все имеющиеся.

## Формат вывода
- Markdown-отчёт с заголовком; в начале указывается применённый фильтр формы (либо «данные по всем формам»).
- **Раздел 1** — таблица: `form_id` | `form_name` | уникальных задач | среднее заполненных полей. Среднее — с двумя знаками после запятой (например, `12.50`). Включаются все формы выборки, для которых есть хотя бы одна задача.
- **Раздел 2** — для каждой формы отдельный блок с подзаголовком (название формы или `form_id`) и таблицей из одной колонки `task_id` (до 3 строк, по убыванию).
- Пустых значений в таблицах быть не должно: формы и задачи без подходящих записей в выборку не включаются.

## Параметры
- Период не предусмотрен датасетами — отчёт строится по всем доступным данным.
- Фильтр номера формы описан в разделе «Фильтры».

## Фильтры
- **t_form** (на фронте), соответствует полю **form_id** (число, bigint): номер формы.
  - По умолчанию задано значение `325175`.
  - В инструменте фильтра на фронте предусмотрена возможность выбрать «все формы» (значение сбрасывается).
  - Если задано значение — в отчёт попадают ТОЛЬКО задачи формы с данным `form_id` (другие формы и лишние значения исключаются на уровне фильтрации до агрегации).
  - Если значение не заполнено (выбраны все формы) — отчёт строится по всем формам без ограничения по `form_id`.
  - Применяется ко всем разделам отчёта и к сводке.
