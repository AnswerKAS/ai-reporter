# Скилл: Количество уникальных задач

## Датасеты: tast-field-details, pyrus

## Цель
Построить отчёт по формам Pyrus: количество уникальных задач по каждой форме, среднее число заполненных полей на задачу, график количества задач по формам и блоки с последними тремя задачами по каждой форме. Отчёт управляется фильтром `t_form` (идентификатор формы): по умолчанию берётся форма `325175`, доступна опция «все формы» (специальное значение `all`).

## Источник данных
Отчёт строится на двух датасетах реестра бэкенда (оба — postgres):

1. **tast-field-details** — детали по задачам в Pyrus (таблица `public.pyrus_form_fields`). Основной источник: из него считаются уникальные задачи, заполненные поля и последние задачи по формам.

   | Поле | Тип | Описание |
   |---|---|---|
   | form_id | bigint | Идентификатор формы |
   | task_id | bigint | Идентификатор задачи |
   | field_id | bigint | Идентификатор поля |
   | row_id | bigint | Идентификатор строки (для табличных/повторяющихся полей в задаче) |
   | field_name | text | Название поля |
   | field_type | text | Тип поля |
   | field_value | text | Значение поля |

2. **pyrus** — реестр форм Pyrus (таблица `public.pyrus_general`). Используется только для получения названий форм по `form_id`: поля `form_id` (bigint) и `form_name` (text). Отдельного датасета `pyrus_task` в реестре нет, поэтому названия форм берутся из датасета `pyrus`.

Используются только поля, перечисленные выше; остальные поля датасетов в запросах не участвуют.

Все расчёты выполняются запросами к источнику данных (SQL-агрегации: `COUNT(DISTINCT ...)`, `GROUP BY`, оконные функции, `ORDER BY`/`LIMIT`) без построчной выгрузки всех строк в клиент — это гарантирует завершение построения отчёта за отведённое время.

## Что должно быть в отчёте
Все секции строятся только по задачам выбранных форм (см. «Фильтры»); задачи, не относящиеся к выбранным формам, в отчёт не попадают.

1. **Таблица «Количество уникальных задач по формам»**: по каждой форме (`form_id` из датасета `tast-field-details`) — название формы `form_name` (из датасета `pyrus`) и количество уникальных задач `COUNT(DISTINCT task_id)`. Сортировка по количеству задач по убыванию; при равенстве — по `form_id` по возрастанию.

2. **Таблица «Среднее число заполненных полей на задачу»**: в разрезе форм.
   - Поле считается заполненным, если в задаче есть хотя бы одна запись с `field_value IS NOT NULL AND btrim(field_value) <> ''`.
   - Несколько строк (`row_id`) одного и того же поля учитываются один раз: заполненное поле считается уникальной парой `(task_id, field_id)`, для которой существует заполненная запись.
   - Метрики по форме: всего задач (`COUNT(DISTINCT task_id)`), всего заполненных полей (число уникальных пар `(task_id, field_id)` с заполненными записями), среднее заполненных полей на задачу = всего заполненных полей / всего задач формы.
   - Среднее округляется до 1 знака после запятой.

3. **График «Количество задач по формам»**: столбчатая диаграмма на mermaid `xychart-beta` (или аналогичный синтаксис, поддерживаемый рендерером). Ось X — `form_id` (подпись — `form_name`), ось Y — количество уникальных задач. Порядок точек по возрастанию `form_id`.

4. **Блоки «Последние 3 задачи по формам»**: для каждой формы — 3 задачи с наибольшим `task_id` (номера задач в Pyrus растут со временем, поэтому последние задачи — это максимальные `task_id`). Карточка задачи: заголовок с `task_id` и список заполненных полей в формате `field_name`: `field_value`. Поле признаётся заполненным по правилу из пункта 2; если у задачи заполненных полей нет — вывести «заполненных полей нет». Задачи внутри блока сортируются по `task_id` по убыванию.

## Формат вывода
Markdown-отчёт со следующей структурой:
- Заголовок отчёта и сводка: применённый фильтр `t_form` (конкретный `form_id` или «все формы»), общее количество задач в выборке, общее количество форм.
- Раздел «Количество уникальных задач по формам» — markdown-таблица с колонками `form_id` | `form_name` | уникальных задач.
- Раздел «Среднее число заполненных полей на задачу» — markdown-таблица с колонками `form_id` | `form_name` | всего задач | заполнено полей | среднее заполненных полей на задачу.
- Раздел «График: количество задач по формам» — столбчатая диаграмма mermaid `xychart-beta` + дублирующая таблица с колонками `form_id` | `form_name` | задач.
- Раздел «Последние 3 задачи по формам» — для каждой формы подзаголовок с `form_id` и `form_name`, внутри — карточки последних трёх задач.
- Числа в таблицах — целые, кроме среднего значения (1 знак после запятой).
- Пустых значений быть не должно: формы и задачи без подходящих записей в выборку не включаются.

## Параметры
| Параметр | Поле датасета | Описание | Обязательный | По умолчанию |
|---|---|---|---|---|
| t_form | form_id | Идентификатор формы для фильтрации отчёта; специальное значение «all» — все формы | Нет | 325175 |

## Фильтры
- **t_form** (form_id, число): точное совпадение со значением `form_id` в датасете `tast-field-details`. По умолчанию `325175`. Специальное значение «all» означает «все формы» — фильтр не применяется, и в отчёт попадают задачи всех форм.
- Фильтр применяется ко всем секциям отчёта (таблицы, график, блоки последних задач) до агрегации: в отчёт попадают только задачи выбранных форм.
