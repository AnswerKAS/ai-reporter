# Скилл: Отчет по полям Pyrus

## Датасеты: pyrus, tast-field-details

## Цель
Единый отчет по форме Pyrus «ИТ поддержка совкомбанка»: заполненность полей по задачам, состав полей типа catalog, повторяющиеся названия полей — с фильтрацией по типу поля (field_type).

## Источник данных
Отчет строится на двух датасетах backend-реестра.

### 1. Датасет `pyrus` (postgres, таблица `public.pyrus_general`) — «ЗАдапайрус»
Используемые поля:

| Поле | Назначение в отчете |
|---|---|
| form_id | Соединение с датасетом `tast-field-details` |
| form_name | Фильтр по форме и подпись формы в заголовке и на диаграмме |
| last_sync_at | «Последняя синхронизация» в резюме |

Примечания:
- Идентификатор датасета в реестре — именно `tast-field-details` (написание реестра, не переименовывать в запросах).
- Поля steps, fields, fields_count, raw, created_at, updated_at, deleted_or_closed, last_task_id **не используются**: число полей в отчете всегда считается по записям `tast-field-details` (COUNT DISTINCT), а не берется из fields_count.

### 2. Датасет `tast-field-details` (postgres, таблица `public.pyrus_form_fields`) — «Детали по задачам в Pyrus»
Основной источник данных:

| Поле | Назначение в отчете |
|---|---|
| form_id | Привязка записей к форме |
| task_id | Группировка таблицы заполненности (одна строка — одна задача) |
| field_id | Идентификатор поля; ключ подсчета уникальных полей |
| row_id | Номер строки табличного поля; входит в ключ уникальности пары (field_id, row_id) |
| field_name | Название поля; анализ повторов в нижнем регистре |
| field_type | Тип поля; фильтр отчета и выделение типа catalog |
| field_value | Значение поля; признак «заполнено» |

Связь датасетов: `pyrus.form_id = tast-field-details.form_id` (многие к одному).

## Что должно быть в отчете

### Блок 1. Резюме (сводка)
Все метрики резюме считаются **после применения фильтров «Форма» и «Тип поля (field_type)»**:
- **Задач в отчете** — COUNT(DISTINCT task_id).
- **Уникальных полей** — COUNT(DISTINCT field_id).
- **Средний % заполненности** — среднее арифметическое индивидуальных процентов заполненности задач (каждая задача весит одинаково, без взвешивания по числу полей), округление до 1 знака после запятой.
- **Названий с повторами** — число групп LOWER(TRIM(field_name)), в которых COUNT(DISTINCT field_id) > 1.
- **Последняя синхронизация** — MAX(last_sync_at) по выбранной форме из датасета `pyrus`, формат DD.MM.YYYY HH:MM.

### Блок 2. Таблица «Заполненность полей по задачам»
Одна строка — одна задача (task_id). Колонки: task_id, Всего полей, Заполнено, % заполненности, Ниже порога.

Правила подсчета:
- **Всего полей (в задаче)** = COUNT(DISTINCT (field_id, row_id)) — уникальность определяется парой (field_id, row_id), чтобы повторяющиеся строки табличных полей считались отдельными ячейками.
- **Заполнено** = COUNT(DISTINCT (field_id, row_id)) при условии field_value IS NOT NULL AND TRIM(field_value) <> ''.
- **% заполненности** = ROUND(Заполнено / Всего полей × 100, 1) — один знак после запятой; задачи с Всего полей = 0 в таблицу не попадают.
- **Сортировка**: % заполненности по возрастанию; при равенстве — task_id по возрастанию.
- **Лимит строк**: параметр «Лимит строк (задачи)», по умолчанию 200; если задач больше — приписка под таблицей «Показаны первые N задач из M».
- **Выделение низкого процента**: строки, у которых % заполненности меньше параметра «Порог заполненности», выводятся **жирным шрифтом** и с пометкой «да» в колонке «Ниже порога» (у остальных — «нет»).

### Блок 3. Диаграмма «Поля типа catalog по формам»
- Показатель: COUNT(DISTINCT field_id) при условии field_type = 'catalog' — каждое поле учитывается один раз, строки row_id счетчик не увеличивают.
- Разрез: форма (form_name из датасета `pyrus`).
- При действующем фильтре «Форма» на диаграмме одна колонка — выбранная форма; значение подписывается над колонкой.
- Сортировка колонок: по значению по убыванию, при равенстве — по названию формы.

### Блок 4. Таблица «Повторяющиеся названия полей»
- Группировка: LOWER(TRIM(field_name)) в пределах выбранной формы (регистр не учитывается).
- Счетчик: COUNT(DISTINCT field_id) — повторения считаются **по уникальным field_id**, записи с разными row_id одного поля счетчик не увеличивают.
- В таблицу попадают только названия, у которых число полей больше 1.
- Колонки: Название (в нижнем регистре), Число полей, field_id (список через запятую), Типы полей (различающиеся field_type через запятую).
- Сортировка: «Число полей» по убыванию; при равенстве — название по алфавиту.
- Лимит: параметр «Лимит повторов», по умолчанию 50; при превышении — приписка «Показаны первые N из M».

## Формат вывода
- Порядок блоков: Резюме → Таблица «Заполненность полей по задачам» → Диаграмма «Поля типа catalog по формам» → Таблица «Повторяющиеся названия полей».
- Заголовок отчета: «Отчет по полям Pyrus — {form_name}».
- Проценты: один знак после запятой (например, 87.5); целые показатели — без дробной части.
- Даты и время: формат DD.MM.YYYY HH:MM (применяется к last_sync_at в резюме).
- Диаграмма: столбчатая (bar chart) с подписями значений.
- Пустые результаты: если после применения фильтров в блоке нет данных — вывести текст «Нет данных по заданным фильтрам» вместо пустой таблицы/графика.
- Терминология: во всех текстах отчета писать «отчет» (без «ё»); названия блоков — с заглавной буквы.

## Параметры
| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| Форма | строка | «ИТ поддержка совкомбанка» | Точное совпадение с form_name; отчет строится только по одной форме |
| Тип поля (field_type) | список строк | пусто (все типы) | Множественный выбор; применяется ко всем блокам отчета, включая резюме |
| Порог заполненности | число, % | 50 | Задачи с % заполненности ниже порога выделяются жирным шрифтом и пометкой «да» в колонке «Ниже порога» |
| Лимит строк (задачи) | целое | 200 | Максимум строк в таблице «Заполненность полей по задачам» |
| Лимит повторов | целое | 50 | Максимум строк в таблице «Повторяющиеся названия полей» |

## Фильтры
1. **По форме**: `pyrus.form_name = {Форма}` с соединением `pyrus.form_id = tast-field-details.form_id`; действует на все блоки отчета.
2. **По типу поля**: `tast-field-details.field_type IN ({Тип поля})` — применяется, если параметр задан; действует на все блоки, включая метрики резюме.
