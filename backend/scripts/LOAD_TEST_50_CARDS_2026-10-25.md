# Нагрузочный тест отчёта с 50 карточками — 25.10.2026

Отчёт: `loadtest-50-cards-multi-dataset` — «Нагрузочный тест · 50 разных карточек · 3 датасета».

Сценарий создания и проверки: [load_test_dashboard.py](load_test_dashboard.py). Запуск из корня проекта после подготовки датасетов сценарием `load_test_reports.py`:

```sh
docker compose exec -T backend python - < backend/scripts/load_test_dashboard.py
```

Отчёт содержит **50 самостоятельных блоков**: 5 KPI, 40 графиков десяти видов и 5 таблиц. Блоки используют датасеты `loadtest_bench_orders`, `loadtest_bench_order_items` и `loadtest_bench_web_events` (исходные таблицы содержат соответственно 10, 8 и 6 млн строк).

Добавлены **6 фильтров**: период и основной разрез для каждого датасета. Разрез заказов выбирается одним значением, категория позиций — несколькими, устройство событий — одним. Проверено, что фильтр региона заказов меняет KPI заказов и сохраняет значения KPI двух других датасетов с учётом округления `Float64`.

## Замеры

Замер API выполнен через локальный backend в Docker с живым расчётом всех 50 секций на ClickHouse. Пять последовательных открытий: медиана **2567 мс**, максимум **2641 мс**. Четыре открытия при параллельности 2: медиана **3904 мс**, максимум **3925 мс**. Ответ около **65 КБ**; все запросы завершились успешно.

Отрисовка проверена в headless Chrome на экране 1440 × 900, три полные загрузки страницы. Браузер показал 50 заголовков блоков, 40 графиков SVG и 5 таблиц; горизонтального переполнения нет. Медиана от навигации до отрисовки — **3226 мс**, из них после окончания API-запроса — **338 мс**.

Это короткий тест в одном браузере на локальной машине. Он показывает время полного открытия тяжёлого отчёта и отрисовки 50 блоков; длительную работу нескольких пользователей не измеряли.
